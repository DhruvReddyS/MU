Diagram 08
Offline Capability Matrix
Every feature — categorised by what it needs and whether it works in a total blackout.
Feature Needs Internet Needs Cell Needs LAN/Hotspot Works Fully Offline Mechanism
View feed messages No No No Yes IndexedDB local read
Compose a message No No No Yes IndexedDB write
View offline map No No No Yes Leaflet + no tile server
GPS location tracking No No No Yes navigator.geolocation
Draw safe route No No No Yes Map tap → waypoints array
Generate station QR No No No Yes qrcode library (bundled)
Scan QR to receive data No No No Yes jsQR + camera API
P2P device connection No No Yes (same LAN) LAN required WebRTC DataChannel
Multi-hop relay No No Yes (per hop) LAN per hop Differential sync protocol
Encrypted DM No No Yes (active link) LAN required ECDH + AES over DataChannel
Bluetooth device discovery No No No Yes (proximity) Web Bluetooth (hint only)
PWA app loading No No No Yes Service Worker precache
Key takeaway: 10 of 12 features work with zero network of any kind. Only live P2P sync requires a shared LAN or hotspot — which is available even when internet and cellular are both cut.
Diagram 09
Fragment Relay System — Bandwidth-Efficient Body Transfer
When a message body is too large to relay in one go, TRINETRA splits it into numbered fragments. Each fragment relays independently and reassembles on the receiving node.
Diagram 10
QR Decode Pipeline — 6-Strategy Per Frame
Every camera frame is processed through six distinct strategies in parallel before jsQR attempts a decode. First success wins. Handles low light, glare, tilt, and partial occlusion automatically.
Diagram 11
Message Types — 7 Types, Visual Reference
TRINETRA supports 7 distinct message types. Each has a recommended priority range, visual treatment in the feed, and a specific use case in a blackout scenario.
Type Priority Range Visual Treatment Map Pin Blackout Use Case
emergency 90–100 Red corner-bracket styling, LIVE pulsing dot, always sorted first ⚠ Red Bridge collapse, curfew, active threat, evacuation order
alert 70–89 Amber border, bold title, sorted near top ! Orange Road blocked, crowd gathering, area to avoid
safe-route 60–79 Green polyline on map, route popup on click, directional indicator → Green + polyline Walkable corridor to safety, alternate road, path through blockade
medical 50–69 Teal cross icon, highlighted body text ✚ Teal First aid station, doctor location, medical supplies available
shelter 40–59 Blue border, shelter icon in card header ⌂ Blue Relief camp, safe building, overnight shelter available
resource 30–49 Amber badge, resource-type icon, expiry prominently shown ◆ Amber Water, food, fuel, charging point, blankets available
info 0–29 Muted styling, sorted below actionable types ℹ Muted Power restored, area update, general community notice
Priority determines relay order: In MSG_HAVE, message IDs are sorted by priority descending. Higher-priority messages are sent first in MSG_BUNDLES. This ensures emergency alerts propagate ahead of general info even when bandwidth is tight.
