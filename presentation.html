03 / 07 — SOLUTION
The Mesh That Doesn't Need The Internet
A fully offline PWA — no server, no cloud, no cellular required
🔗
PEER-TO-PEER FIRST
Devices connect directly over LAN via WebRTC. No signalling server. The handshake happens through QR codes scanned between phones.
📶
MESH RELAY
A message from Device A reaches Device C through Device B — multi-hop propagation without any central coordinator.
💾
OFFLINE STORAGE
All data lives in IndexedDB on-device. Messages auto-expire via TTL. Nothing leaves the device unless you choose to share it.
📷
QR TRANSPORT
No Wi-Fi? No problem. Scan a QR code to transfer messages between devices — just two phones and a camera.
🔒
ENCRYPTED DMs
End-to-end encrypted 1-on-1 messaging using ECDH key exchange over the WebRTC data channel.
🗺️
OFFLINE MAPS
Pin safe routes, hazards, and shelters on a fully offline Leaflet map. Export and share location data via QR or peer sync.

04 / 07 — ARCHITECTURE
System Architecture
📱
Device A
💻
Device B
📱
Device C
📟
Device D
🕸️
QR HANDSHAKE
💾 IndexedDB
01
QR CODE HANDSHAKE
Device A encodes its SDP offer into a QR code. Device B scans it and generates an answer QR. No signalling server needed.
02
WebRTC DATA CHANNEL
Once the handshake completes, a direct RTCDataChannel opens between peers on the local network for real-time messaging.
03
MESH RELAY PROPAGATION
Messages carry TTL, revision, and hop-count metadata. Each peer relays to its connected nodes — forming a multi-hop mesh.
04
IndexedDB PERSISTENCE
All messages, keys, contacts, and map pins are stored locally. Conflict resolution uses revision numbers — highest revision wins.
